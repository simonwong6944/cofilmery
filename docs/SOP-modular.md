# CoAppery 模組化開發 SOP

> 本文件管「點樣分模組、點樣砌頁」:程式碼結構規則。
> 與 SOP-workflow.md（流程）、Rules.md（內容語體）、Architecture.md（設計意圖）並行。
> 本文件屬「狀態類」文件:可編輯,但每次修改須喺文件底「修訂記錄」加一行。

## 一、目的

規範 CoAppery / CoFilmery 前後端程式碼嘅切分方式,令每個檔案細、可測、可獨立修改,避免一改牽全身。

## 二、三層架構

1. 共用模組（shared modules）:跨頁面共用嘅工具、adapter、型別、常數。
2. 複合模組（composite modules）:由共用模組組合而成、對應某功能區塊嘅中層模組。
3. 頁面檔（page files）:最外層,負責組裝複合模組成一版頁面,本身唔應該塞太多邏輯。

## 三、硬規則 A–F

- A:三層職責分明,唔准跨層塞邏輯（頁面唔寫底層工具、共用模組唔寫頁面專屬邏輯）。
- B:行數上限——頁面檔 ≤200 行,模組（共用／複合）≤250 行。超標即拆。
- C:一次改動只准動所屬模組;要改到第個模組,先停低,記入 pending_changes.md。
- D:唔准硬編碼密鑰／可配置參數（積分、時限等）——一律入 config／env secret。
- E:新增功能優先復用現有共用模組,唔好重複造輪。
- F:所有改動要可通過 wc -l、grep、npm run build 三項 gating（見 SOP-workflow.md）。

## 四、標準流程

1. 拆磚:將功能拆成最細可交付單位,每磚對應一個模組或一版頁面。
2. 審視:確認落喺邊一層,對照硬規則 A–F。
3. 建模組:寫共用／複合模組,守 ≤250 行。
4. 組頁:喺頁面檔組裝模組,守 ≤200 行。
5. 驗證:wc -l + grep + npm run build 全過。
6. 只改所屬模組修 bug:發現問題,只動出問題嘅模組,唔連帶亂改其他檔。

## 五、與 Rules.md 嘅關係

- 本文件管「結構／行數／分層」;Rules.md 管「內容／語體／紅線」。
- 兩者衝突時,以產品負責人裁決為準,並記入 pending_changes.md。
